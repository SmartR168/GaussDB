# 实验五：金融场景综合实践

## 依据与评分

依据课程说明第6—9页及《GaussDB案例》5.1—5.7。基础30分逐项覆盖；进阶20分按技术深度8、改进价值6、流程与验证6综合评价，不将两个方向简单等同于每项10分。

## 基础验收

- 独立finance数据库、UTF8、普通开发用户db_dev、归属db_dev的finance模式。
- ER图及四表client、bank_card、financial_product、financial_asset，讲义原始字段和10/10/4/4条种子数据。
- JDBC连接、版本与驱动记录，数据库对象初始化、DAO CRUD与testDAO断言。
- Service、FlowControl、launch：客户查询及详情、开户、修改、销户、开卡、销卡、产品查询、申购与赎回；失败不得报告成功。
- DN主备切换：切换前后节点角色与任务成功；切换后重新连接核对完整数据。
- 备份策略：保留5天、周六与周日；保存后重读；手动备份成功。
- autoanalyze设为on，保存任务成功；独立gsql执行SHOW核对。
- db_dev查询系统目录表和索引；普通test用户经历无模式权限、仅模式权限、表SELECT授权后三阶段验证。
- 实际日志、截图、独立gsql核对；可按README复现。

## 两项进阶

1. 数据查询与分析：客户资产与卡数汇总、产品持仓、半开日期区间的月度统计。先聚合卡和资产再关联，验证多卡多资产不会重复求和，零持仓客户保留、冻结资产单列、月界记录正确归属；导出CSV报表。
2. 数据正确性与可靠性：申购/赎回同步写业务表、请求表及事件记录；事务失败回滚；请求号与完整业务参数摘要绑定；并发重复申购只生成一笔；同一资产并发赎回只成功一次；有卡或资产时禁止销户。每个并发线程使用独立连接，验证数据库最终状态。

## 进阶评价对应

技术深度：跨表事务、唯一约束、行锁、并发竞争、重复请求参数校验；多对多关联汇总的口径与边界。

改进价值：修复示例吞掉SQL异常、影响0行仍报成功、重复提交造成重复交易、销户先检查后操作存在竞争、多表直接连接导致金额重复等问题。

完整验证：正常、非法参数、重复主键/外键、不存在记录、冻结赎回、注入故障回滚、相同请求不同参数、真实并发、报表独立期望值、gsql交叉核对配套；仅记录真实执行结果。

## 数据口径与范围

保留讲义a_quantity作为申购金额、a_income作为收益金额的字段口径，原始示例数据为4/3/2/1及8001—8004；不据此推导真实投资回报率。p_amount保留讲义产品购买金额字段，不额外解释为最低申购门槛。实验只实现讲义的理财产品a_type=1，不虚构保险或基金表。

新增外键与非负/正数约束加强模型，原始字段及种子值不变。赎回按讲义删除持仓行，扩展事件表保存历史；普通业务操作不删除历史事件。命令行界面足以满足课程基础要求。
